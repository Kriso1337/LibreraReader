# План реализации каталога и редизайна Librera

Статус: проектирование, 2 ноября 2026 года. Android-реализация в этот этап не входит. Проверена кодовая база upstream `ec7a0bede06ef514b317b7cf8639362d26c67b95` (`10.0.22`); рабочий форк — `Kriso1337/LibreraReader`.

## Решение

Добавить самостоятельную вкладку **«Каталог»** с источником «Флибуста»: поиск, навигация по авторам и жанрам, карточка книги, доступные форматы, загрузка, открытие локального экземпляра. Пользователь скачивает выбранные книги; приложение подгружает страницы каталога по мере просмотра. Полное выкачивание базы или файлов библиотеки не требуется.

Получать каталог через OPDS. HTML-парсинг страниц оставить отдельной будущей возможностью только для данных, которых нет в feed. Доступность форматов определяется реальными acquisition-ссылками: интерфейс не обещает скачать отсутствующий файл и не генерирует URL форматов по догадке.

Каталог, загрузки и хранение отделить от движка чтения. Внедрение начать в существующем Java/Views-приложении. Полный редизайн оболочки проводить следующим этапом на тех же компонентах данных, без одновременного переписывания reader, TTS, конвертеров и облачной синхронизации.

### Сборки и ограничения

- `gradle/libs.versions.toml:42` задаёт `targetSdk=36`, `compileSdk=37`, `minSdk=24`, JDK target 21; это данные checkout, а не предположение о настроенной машине.
- `app/src/main/AndroidManifest.xml:17` содержит `INTERNET`. `app/src/fdroid/AndroidManifest.xml` его не удаляет; запрет OPDS для F-Droid в `UITab.isVisible()` закомментирован. В текущем коде сетевой каталог технически возможен и в F-Droid flavor. Не переносить старое описание «F-Droid без Internet» из README как фактическое ограничение этой версии.
- `app/build.gradle:122` и `:152`: есть `fdroid` и `fdroidJS`; JS-вариант меняет движки документов. Их нужно включить в матрицу проверки открытия скачанных книг, не менять flavor ради каталога.
- Manifest уже разрешает cleartext для существующих функций. Новый клиент каталога должен иметь собственную HTTPS-политику; не менять глобально поведение остальных источников без отдельной проверки.
- В `gradle/libs.versions.toml:137` OkHttp закреплён на 3.12.6 с комментарием о несовместимости новых версий. Обновление всей сети не является скрытой зависимостью MVP.
- `CLAUDE.md` требует синхронных переводов новых строк во всех `values-*/strings.xml`, сохранения позиции строк и идентичности Hebrew `values-he`/`values-iw`. Включить эту работу в Android-этап.

## Предлагаемые границы компонентов

Названия ниже — проектируемые компоненты, их пока нет в Android-коде.

```text
CatalogFragment / BookDetails / DownloadsScreen
             ↓ наблюдение состояния + команды
CatalogRepository            DownloadRepository
  ├─ CatalogHttpClient         ├─ persistent DownloadTask store
  ├─ OpdsParser                ├─ DownloadScheduler (выбор после spike)
  ├─ MirrorResolver            ├─ transfer / validation / finalization
  └─ metadata + cover cache     └─ StorageGateway
                                      ↓
                              LocalBook / FileMeta bridge
                                      ↓
                              ExistingReaderAdapter
                                      ↓
                         ExtUtils.openFile → текущий reader
```

Для MVP реалистичен новый пакет `com.foobnix.catalog` внутри `app`, чистые Java-классы парсинга/URL и новые Views/RecyclerView-экраны. Вынесение отдельного Gradle-модуля или переход на Compose — последующее решение. ViewModel либо иной переживающий пересоздание экрана state holder хранит UI-состояние; Activity/Fragment не владеет сетевыми потоками и сохранённой очередью.

Сущности:

- `CatalogSource`: стабильный `sourceId`, набор разрешённых endpoint, выбранный пользователем endpoint, настройки прокси.
- `RemoteBook`: `(sourceId, remoteBookId)`, авторы, название, языки, описание, ссылки форматов и изображений. Если ID непригоден — отдельная нормализация в адаптере источника, без привязки идентичности к домену зеркала.
- `DownloadTask`: ID книги и формата, URL попытки, состояние, байты, ETag/Last-Modified при наличии, путь временного файла, итоговый `contentUri`/path, ошибка и время следующей попытки.
- `LocalBook`: связь с remote ID, выбранный формат, имя файла, URI/путь, размер, fingerprint при необходимости, стабильный ключ для существующей истории чтения.

Сначала выбрать способ хранения новых сущностей: миграция существующей greenDAO-схемы или отдельная небольшая SQLite/Room-база. Не редактировать генерируемые DAO вручную. Решение принять после проверки генерации и сохранения данных при обновлении, а не автоматически вводить вторую ORM.

## Зеркала и ссылки

1. Стартовый список: `https://flibusta.is/`, `https://proxy.flibusta.is/`, `https://flibusta.site/`. Адрес `x.flibusta.is`, найденный при исследовании, — дополнительный кандидат. Проверенные HTTP 200 и OPDS на 02.11.2026 не являются обещанием постоянной доступности или доказательством принадлежности зеркала.
2. Проверять небольшой `/opds` по HTTPS: статус, MIME, валидный Atom и ожидаемую структуру. HTML заглушку, captive portal, captcha и пустой feed классифицировать отдельно. Не скачивать каталог целиком для health-check.
3. Не внедрять автоматическое доверие доменам из форумных сообщений. Скрипт исследования может предлагать кандидатов человеку; приложение использует встроенный список, ручной URL или будущий подписанный обновляемый список. Новый чужой домен не получает cookies/Authorization прежнего.
4. Ссылки разрешать стандартным URI/HttpUrl resolver относительно **финального URL ответа страницы**, учитывая query, `../`, `/`, `//` и `xml:base`, если поддерживается. Текущий `Hrefs.java:9` собирает URL строками и превращает `//` в HTTP; не переносить это поведение в новый слой.
5. Разрешённые схемы для сетевого клиента — HTTPS; явный HTTP для особого пользовательского источника, Tor/I2P или прокси требует отдельного режима и тестов. Отбрасывать `javascript:`, `file:`, `content:` и неожиданные сетевые схемы в удалённом feed. Изображения и загрузки проходят ту же проверку URL/redirect.
6. Failover переключает базовый endpoint только для путей, принадлежащих адаптеру этого источника. Не переписывать строкой произвольные внешние ссылки, подписанные URL или ссылки оплаты. Книжная сущность сохраняет ID при смене домена.
7. Повторять ограниченно при network timeout/5xx; учитывать `Retry-After` при 429. 401/403, отсутствие формата, 404 конкретной книги и ошибка сертификата не означают автоматически, что весь сайт надо считать упавшим. Показывать причину и возможность ручного выбора.
8. Смена сети или endpoint отменяет устаревшие запросы; ответ предыдущего поиска не заменяет новый. У health-check есть TTL/backoff, у страниц кеша — собственная актуальность.

Парсер должен ограничивать размер XML, глубину и количество элементов, запрещать DTD/внешние сущности, обрабатывать namespaces и отсутствующие атрибуты. Текущий `XmlParser.java:12` не задаёт явного запрета DOCTYPE: для нового парсера нужен отдельный контракт и отрицательные тесты. Описание очищать от активного HTML; сетевое содержимое не выполнять в WebView. Не записывать пароли, cookies, Authorization и полные секретные URL в логи.

## Загрузка и локальное хранение

Состояния задания: `queued → connecting → downloading → verifying → saving → completed`; боковые состояния `waiting_network`, `paused`, `failed`, `cancelled`, `needs_storage_access`. Состояние сохраняется независимо от UI. Поворот экрана и уход из приложения не создают вторую загрузку.

В MVP предусмотреть возобновление очереди после пересоздания процесса и повтор всей прерванной передачи. Побайтовое докачивание — только при подтверждённой поддержке Range/валидатора сервером: нельзя склеивать байты разных зеркал или новых версий файла. Пауза без Range сохраняет намерение пользователя, но следующий запуск может начать передачу заново; показать это честно.

Скачивать во временный app-private файл с лимитом размера и проверкой свободного места; проверять статус ответа, Content-Type и сигнатуру формата. HTML-страница ошибки с кодом 200 не становится EPUB. EPUB/FB2 ZIP дополнительно проверять на структуру и ограничения распаковки. После проверки записывать в выбранное пользователем хранилище и только затем публиковать `completed` и запись локальной библиотеки. Повтор по `(sourceId, bookId, format)` не создаёт дубликат без явного выбора. Существующий файл не удалять до успешного сохранения нового.

SAF даёт URI выбранной папки/документа; разрешение следует сохранять через `takePersistableUriPermission`. URI может стать недоступным после перемещения документа, удаления или отзыва доступа, поэтому предусмотреть повторный выбор папки. `ACTION_OPEN_DOCUMENT_TREE` имеет ограничения на доступные системные каталоги на новых Android. [Официальное описание Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files).

**SAF commit не считать файловым atomic rename:** возможности rename/delete и поведение провайдера отличаются. `StorageGateway` должен различать filesystem и document-provider операции. Для SAF либо сначала создать временный документ и переименовать при поддержке, либо копировать проверенный временный файл в итоговый документ, отмечая задачу завершённой только после успешного закрытия потока. При сбое удалять лишь созданный этой задачей незавершённый документ и сохранять возможность повторить; учитывать необходимость места на staging + окончательную копию.

**Reader bridge:** локальный экземпляр сохраняет оригинальный content URI и стабильную связь с cache path. Первое открытие через существующий `ExtUtils.openFile` может создать копию. Проверить работу `CacheZipUtils.getSafBookCopy`, возврат из истории, обновление файла, очистку кеша и сохранение закладок. Не заменять content URI на случайный temp path и не обещать «без копирования». Для неподдержанного reader-потока ввести узкий адаптер, не переписывать все кодеки.

### Обязательный spike механизма фоновой загрузки

Долгие WorkManager workers используют foreground service и уведомление, однако на Android 16 могут расходовать job quota. Поэтому нельзя обещать бесконечный или гарантированно непрерываемый Worker. [Android: long-running workers](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running).

Для длительной передачи по нажатию пользователя проверить UIDT jobs на API 34+, а для младших API — подходящий WorkManager foreground fallback. UIDT требует пользовательского запуска, уведомления и подходящих условий; ОС также может остановить задание. Сохранять прогресс независимо от вызова `onStopJob`. [Android: user-initiated data transfer](https://developer.android.com/develop/background-work/background-tasks/uidt).

Результат spike: выбранный scheduler для коротких/длинных загрузок, схема уведомления и cancel, обработка background-start restrictions, stop/quota/reboot, проверка API 24/30/34/36. Не менять существующий TTS service для загрузок. Download engine и persisted queue должны оставаться независимыми от выбранного scheduler.

## Проверки и критерии готовности

Использовать существующие `app/src/test` и `app/src/androidTest`; добавлять тесты поведения, а не копии реализации. Для сети — фикстуры и локальный HTTP test server/MockWebServer, а живые зеркала проверять отдельным smoke test: их доступность не должна ломать основной CI.

- Парсер: navigation/acquisition feed, namespace, Unicode, несколько авторов, отсутствующий MIME/ID/обложка, OpenSearch, `next`, malformed/oversized XML, DTD, вредоносное описание.
- URL: root-relative, path-relative, query-only, `../`, `//`, редирект на другое origin, запрет downgrade и неразрешённых схем; отсутствие передачи credentials новому origin.
- Сеть: timeout, DNS/TLS error, 429/Retry-After, 5xx, 401/403, HTTP 200 с HTML вместо feed/файла; ограничение попыток и отмена старых результатов.
- Загрузки: повторное нажатие, две книги одновременно, смена сети, закрытие экрана, смерть процесса, остановка системой, cancel, неполный файл, смена ETag, неверный Content-Length, неизвестный размер.
- Хранилище: внутренняя память/SD через SAF, отказ или отзыв permission, нехватка места, одинаковое имя, неподдерживаемый rename, частичная запись, сохранность ранее скачанной книги.
- Чтение: EPUB, FB2/FB2.ZIP и один крупный PDF; открытие в выбранных flavor, история/закладки после повторного открытия и очистки допустимого кеша, офлайн-доступ.
- Миграции: сохранение `tabsOrder9`, старых каталогов и `FileMeta`; отсутствие автоматического скрытия нужных пользователю вкладок; новый tab ID добавляется один раз.
- UX: минимум 48 dp для основных Android touch targets, TalkBack, 200% размер шрифта, узкий экран, светлая/тёмная тема, понятный статус отсутствующего файла и потерянного доступа.

Плановые команды после подтверждения Gradle-задач и настройки SDK/NDK: `./gradlew :app:testFdroidDebugUnitTest :app:assembleFdroidDebug`, затем instrumented smoke tests на устройстве и соответствующая проверка `fdroidJS`. Эти сборки сейчас не запускались и не объявлены успешными.

Первая версия готова, когда пользователь открывает «Каталог», находит книгу, выбирает **реально доступный** формат, сохраняет в выбранную папку, видит её в локальной библиотеке и открывает без сети. Ошибка сайта, нехватка места или потеря разрешения дают восстановимый сценарий, а не ложное состояние «Скачано».
