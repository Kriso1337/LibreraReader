# Librera: каталог и редизайн

Проектирование отдельной вкладки Флибусты и нового интерфейса Librera с сохранением существующих возможностей. Подготовлено 2 ноября 2026 года для форка [Kriso1337/LibreraReader](https://github.com/Kriso1337/LibreraReader), на базе upstream-коммита `ec7a0bede06ef514b317b7cf8639362d26c67b95`.

**Выбрана «Книжная полка». Добавлен первый Android-этап: отдельная вкладка каталога, поиск OPDS, локальные загрузки и адаптивная компоновка для планшетов 10–12″.** Полный перенос оболочки и читалки остаётся следующим этапом. Подробности и границы проверки — в [отчёте Android](ANDROID.ru.md).

- [Исходник макета](prototype.fragment.html) — редактируемая разметка, стили, демонстрационные данные и сценарии.

python3 -m http.server 8080 --bind 127.0.0.1

Открыть [локальный прототип](http://127.0.0.1:8080/design/catalog-redesign/prototype.html). Сервер нужен только для просмотра. Android SDK не требуется.

## Что проверить в макете

1. Переключить варианты «Книжная полка» и «Компактный каталог».
2. В «Каталоге» найти книгу по названию или автору.
3. Открыть карточку, выбрать формат, запустить загрузку.
4. Перейти в «Мои книги» и открыть сохранённую книгу.
5. Проверить очередь загрузок, выбор источника и поведение без сети.

Книги, размеры, форматы и ход загрузки — демонстрационные данные. Прототип не обращается к Флибусте, не сохраняет книги на диск и не реализует Android Storage Access Framework. Успешная анимация загрузки показывает сценарий интерфейса. Папка «Книги / Librera» — подпись; системный выбор папки войдёт в Android-этап. Reader показывает короткие отрывки классики, а добавление закладки — уведомление без реализации хранения аннотаций. Пауза/докачка моделируются для проверки UX и требуют проверки сервера в реальной реализации. Самостоятельный HTML использует внешнюю библиотеку иконок; для их первого отображения может потребоваться интернет.

## Принятые решения

- Четыре основных раздела: **Читаю / Мои книги / Каталог / Ещё**.
- Отдельная вкладка для онлайн-каталога; Флибуста — первоначальный источник.
- Получать страницы OPDS и OpenSearch по запросу, без массовой выгрузки всей библиотеки.
- Скачивать предлагаемые источником файлы в выбранное локальное хранилище, показывать состояния и повторные попытки. Доступность каждого файла зависит от источника.
- Сначала спроектировать новую оболочку и каталог; перенос читалки и её расширенных функций проводить отдельными проверяемыми этапами.
- Поиск новых зеркал через форум полезен для ручной диагностики. Приложение не должно автоматически доверять произвольным адресам из пользовательских сообщений.

## Источники и границы проверки

Ранее с рабочего компьютера проверены главные страницы и корни OPDS `flibusta.is`, `proxy.flibusta.is`, `flibusta.site` и найденного на резервном форуме `x.flibusta.is`: HTTP 200 и корректный Atom-каталог. Проверка не доказывает доступность из любой сети и не проверяет скачивание каждого файла.

- [Главная Флибусты](https://flibusta.is/) публикует резервный форум, Tor и I2P.
- [Резервный форум](https://librusec.ucoz.de/forum/26) — источник объявлений и кандидатов для проверки.
- [Корень OPDS](https://flibusta.is/opds) содержит ссылки навигации и поиска.
- [Официальные исходники Librera](https://github.com/foobnix/LibreraReader) — основа анализа существующего Android-кода.

Проверки прототипа и снимки экранов описаны в [QA.ru.md](QA.ru.md). Макет не заменяет проверку на Android-устройстве: системное масштабирование текста, TalkBack, поведение процесса в фоне и разрешения на файлы требуют отдельного этапа.
